# Cloudflare Pages cutover

This runbook records the staged move of the new Onovich site to Cloudflare Pages without interrupting the current Cargo site or the GitHub Pages project-site namespace.

As of 2026-08-26, `onovich.com` serves the bilingual portfolio through Cloudflare, and the GitHub Pages user site is mapped to `game.onovich.com`. That host is the shared path namespace for project sites such as `game.onovich.com/2DProGolf/`. `blog.onovich.com` remains unchanged as a short compatibility window while its path-preserving redirect is configured. The root portfolio copy is not intended to be a second production host: the host-aware redirect in `BaseLayout.astro` sends pages generated by this repository to `onovich.com` while leaving other repositories' project paths available.

## Deployment target

- Repository: `onovich/onovich.github.io`
- Production branch: `main`
- Production host: `https://onovich.com`
- Target GitHub Pages namespace: `https://game.onovich.com/<repository>/`
- Framework preset: Astro
- Root directory: `site`
- Build command: `npm run build`
- Build output directory: `dist`
- Required Node version: `22.12.0` or newer, matching `site/package.json`

## Build baseline

This replacement intentionally moves the project from Astro 6 to Astro 7 and adds the static sitemap integration. It is a build/SEO baseline change, not a presentation feature: `npm run build`, the asset check, the visual guard, and `npm audit --omit=dev` must all pass before the branch is considered ready for preview.

## First preview activation (historical)

Cloudflare Pages reacts to new Git events after its GitHub integration is connected. The initial preview trigger is now historical; do not create another documentation-only trigger solely for preview activation unless the Pages project has been recreated.

## Safe rollout

1. Connect the GitHub repository to a new Cloudflare Pages project.
2. Keep `main` as the production branch and let the feature branch create a preview deployment.
3. Review the preview deployment before merging: desktop, mobile, English, Chinese, all art categories, photo albums, lightboxes, links, metadata, and the custom 404 page.
4. Merge only after the visual review is approved.
5. Add `onovich.com` and `www.onovich.com` as custom domains to the Pages project.
6. Redirect `www.onovich.com` to `https://onovich.com` with a Cloudflare Redirect Rule. Domain-level redirects are not supported by a Pages `_redirects` file.
7. Keep unrelated DNS records, including mail and all existing product subdomains, unchanged.
8. Verify HTTPS and the checks below before treating Cloudflare as production.

The `site/public/CNAME` and GitHub Pages workflow now use `game.onovich.com`. Keep the `blog` DNS record until its compatibility redirect is configured and verified; removing it first can break existing paths such as `/2DProGolf/` and other repository pages.

The recommended migration sequence is:

1. [x] Verify `onovich.com` at the GitHub account level, add `game.onovich.com` as the user-site custom domain, and create the DNS CNAME `game.onovich.com → onovich.github.io`.
2. [x] Confirm that project Pages without their own CNAME resolve at `game.onovich.com/<repository>/`, including `2DProGolf` and `GameLetter`.
3. [x] Change `site/public/CNAME` to `game.onovich.com` after the Pages custom-domain setting and HTTPS certificate became ready.
4. Configure `blog.onovich.com` as a compatibility redirect that preserves the path: `/2DProGolf/` → `/2DProGolf/` on `game.onovich.com`; the old root may redirect to `https://onovich.com/`.
5. Keep the browser bridge as a fallback for portfolio pages, then replace it with a server-side redirect only if the DNS/Cloudflare setup can preserve arbitrary project paths safely.

## Cargo URL preservation

`site/public/_redirects` permanently maps the former Cargo paths to their closest new pages. After deployment, verify at least:

- `/game` → `/games-and-tools/`
- `/codes` → `/games-and-tools/`
- `/pixel` → `/art/pixel/`
- `/illustrator` → `/art/illustration/`
- `/photo_1` → `/art/photography/tokyo/`
- `/poem` → `/art/poetry/`
- `/sns` → `/contact/`

When `blog.onovich.com` is moved off GitHub Pages, redirect that hostname with a Cloudflare Redirect Rule or Bulk Redirect, not with the Pages `_redirects` file. Preserve the path suffix for existing project links and send only the old root to `https://onovich.com/` if no separate blog landing page is needed.

## Retiring Cargo

Do not cancel Cargo before the new domain is live. Keep the old site available during a short observation window, check redirects and search-console coverage, and retain an export or account-level backup. After the replacement has remained stable, disable the Cargo subscription renewal; do not delete the old account or site until its assets and content are confirmed recoverable.
